## 1. How `bulk --intervals 1h` works, and where data lands

- `uv run crypto-trade bulk --symbols <SYM> --intervals 1h` lists monthly ZIP archives on
  `data.binance.vision` (S3 `data/futures/um/monthly/klines/<SYM>/1h/`), downloads only months
  not yet covered locally (`compute_missing_months` vs the CSV's last `open_time`), dedups,
  appends. Incremental and resume-safe at month granularity. 3 HTTP retries with backoff on
  429/5xx inside the engine; per-symbol exception tolerance inside `bulk_fetch_all`.
- **Caveat:** the CLI exits 0 even when a symbol yields no data (per-symbol tolerance swallows
  errors). The driver's ledger `OK` therefore means "process completed" — the coverage check
  (§4, `klines_1h_coverage_check.py`) is the actual completeness gate, per charter §4.
- Data lands at `data/<SYM>/1h.csv`. The worktree's `data/<SYM>` entries are **symlinks to the
  main trunk** (`/home/roberto/crypto-trade/data/<SYM>/`) — same sharing pattern as 8h klines,
  funding, and OI. Every scope symbol comes from the 8h panel, so its symlinked dir already
  exists; all 1h CSVs land in the trunk and are visible to all worktrees. Verified: 0 real
  (non-symlink) symbol dirs were created in the worktree by this fetch.
- Monthly ZIPs only — coverage ends 2026-06-30 23:00 (2026-07 has no monthly archive yet).
  `--api-backfill` was deliberately NOT used: DIAG-B/E2 are IS-only (IS ends 2025-12-31), and
  the dispatch asked for rate-limit courtesy toward the concurrently-running OI backfill
  (16 workers on fapi + vision). Current-month 1h can be added later if ever needed.
